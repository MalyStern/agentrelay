# AgentRelay — מסמך-אב לתכנון ובנייה

> **מה זה המסמך הזה.** קיבלתי את האפיון המלא של AgentRelay וביקשת שאחקור לפרטי-פרטים איך לבנות אותו לכל מערכות Claude Code / Codex על Mac, Windows ו-Linux, עם תמיכה בכל השפות, ובצורה יציבה ומהימנה — ואז לרדת לרזולוציות קטנות: איך כל דבר מתבצע. עבדתי לבד. זה מה שיצא.

> המסמך בנוי כך שאפשר להתחיל לכתוב קוד ממנו. כל החלטה טכנית מלווה בסיבה, וכל מנגנון-ליבה מלווה במימוש קונקרטי (סכמה, שם-מתודה, קוד-hook). בסוף יש **שאלות פתוחות שדורשות החלטה שלך** ותוכנית-בנייה בשלבים אטומיים.
>

<a name="1"></a>
## 1. סיכום מנהלים — ההחלטות הגדולות

הבחירות הבאות מקבעות את כל השאר. הן נגזרות מהמחקר, לא מהעדפה שרירותית.

| נושא | ההחלטה | למה |
|------|--------|-----|
| **שפת הליבה (Daemon)** | **Rust** | ניהול-תהליכים, signals, kill-tree, שרת מקומי ו-SQLite — כולם קלים ובטוחים ב-Rust; חבילה יחידה ללא runtime. תואם לאפיון. |
| **מעטפת ה-GUI** | **Tauri 2** (Rust core + WebView) | binary אחד, קטן, חוצה-פלטפורמות; אותו קוד-Rust משמש ל-daemon; יש plugins ל-shell/sidecar/notification/process. |
| **פרונט-אנד** | **React + TypeScript + Vite** | אקוסיסטם עשיר ל-RTL/i18n, timeline virtualization, נגישות. |
| **אחסון** | **SQLite מקומי** (עם WAL) דרך `sqlx` | עמיד, בלי שרת, מתאים ל-event-log + state. |
| **מודל-הליבה** | **Event Sourcing** | ה-Timeline, ה-audit, ה-resume וה-drift-detection *כולם* נגזרים מאותה עובדה: כל דבר שקורה נרשם כאירוע בלתי-משתנה. זה לא feature — זו הליבה. |
| **חיבור ל-Claude Code** | **Claude Agent SDK** (ראשי) + **CLI headless** (גיבוי) + **Hooks** (אכיפה) | ה-SDK נותן שליטה תכנותית מלאה על sessions/resume; ה-Hooks נותנים אכיפה דטרמיניסטית בקוד ולא בפרומפט. |
| **חיבור ל-Codex** | **App-Server (JSON-RPC על Unix socket / stdio)** ראשי + **`codex exec --json`** לצינון-משימות | ה-App-Server הוא הממשק הרשמי; יש בו `turn/interrupt`, `thread/resume`, `thread/fork`, ואירועי-usage. |
| **גבול-אמון** | הוראות = **רק** מהמשתמש. כל מה שמגיע מכלי (README, פלט-סוכן, plugin, memory) = **מידע, לא פקודה** | זה גם עקרון-אבטחה של המערכת עצמה וגם ההגנה מפני prompt-injection שהאפיון דורש (8.9). |
| **ברירת-מחדל בטיחותית** | Overnight מתחיל ב-**deny-all** על פעולות בלתי-הפיכות | אין Deploy/Push/רכישה/מחיקה-מחוץ-ל-workspace בלי אישור מפורש. |
| **חיסכון-מכסה** | **Context Optimizer = מודול-ליבה** (מנוע ניהול-הקשר ותקציב), לא כלי-קיצור | מחזק ישירות את הבטחת-המוצר: יותר-עבודה-בכל-מכסה, פחות-עצירות, פחות-קריאה-חוזרת. מסמך נפרד: [`01-context-optimizer.md`](01-context-optimizer.md). |

**המשפט שמנחה הכל:** *כל מצב שמוצג בממשק חייב לנבוע ממצב-אמת של המערכת, לא מהערכה של מודל.* "ממתין" = התהליך באמת עצר. "עצור" = כל עץ-התהליכים מת. זו הדרישה מ-8.14, והיא שיקול-על בכל מודול.

## 2. מטריצת-יכולות מאומתת: מה כל ספק באמת נותן

זה הבסיס לכל ה-Adapters. חקרתי כל ממשק. **מה שמסומן "מאומת" נבדק במקורות; "לבדיקה" = דורש אימות-שדה בשלב-1** (ראו §17).

### 2.1 Claude Code

| יכולת | מנגנון | סטטוס | הערה למימוש |
|-------|--------|-------|-------------|
| הרצה תכנותית | `claude -p --output-format stream-json --input-format stream-json` (דו-כיווני) | מאומת | NDJSON פנימה והחוצה → פרסינג-אירועים בזמן-אמת |
| שליטה מלאה (מומלץ) | **Claude Agent SDK** (TS + Python), send/stream, hooks, 20+ tools | מאומת | ה-daemon יריץ subprocess של node/python שמריץ SDK, או יקרא ל-CLI ישירות |
| שמירת/שחזור session | ה-SDK כותב session לדיסק; `session_id` בכל `result`; `--resume <id>` / `--continue` | מאומת | **זה עוגן ה-resume שלנו** |
| חסימת קריאת-כלי (אכיפה) | Hook **PreToolUse**, `exit 2` → חוסם + stderr חוזר לסוכן כסיבה | מאומת | חוסם **לפני** בדיקת-הרשאות — עובד גם תחת `bypassPermissions` |
| מניעת "סיום מוקדם" | Hook **Stop**, `decision:"block"` + reason → מכריח להמשיך | מאומת | ככה כופים "אל תסיים עד שהבדיקות עוברות" |
| ראיית-פלט/משוב | Hook **PostToolUse** — רואה תוצאה, יכול להזריק משוב/להחליף פלט | מאומת | הזנת ולידציה חזרה לסוכן |
| אירועי-מחזור נוספים | ~30 אירועי-hook: UserPromptSubmit, Notification, PreCompact, SessionStart/End, SubagentStop | מאומת | Notification/SessionEnd → מזינים את ה-Timeline וה-Signal Hub |
| הודעות מתוזמנות | תוך-session (queue בין turns) + Desktop scheduled tasks (session חדש, דורש אפליקציה פתוחה + מחשב ער) | מאומת (מהאפיון) | לבדיקה מדויקת ב-Win/Mac |

### 2.2 Codex (CLI + App)

| יכולת | מנגנון | סטטוס | הערה |
|-------|--------|-------|------|
| ממשק רשמי מלא | **App-Server** JSON-RPC (stdio/Unix-socket) | מאומת | הבסיס ל-Codex-adapter |
| פתיחת-שיחה עמידה | `thread/start` → `thread/started` | מאומת | Thread שורד restart, resume-by-id, fork, archive |
| הרצת-turn | `turn/start` → stream של `item/*` + `turn/completed` (עם token usage) | מאומת | `turn/completed` נותן usage → מזין Quota Manager |
| הזרקה ל-turn חי | `turn/steer` | מאומת | לשלוח הנחיה בלי להתחיל turn חדש |
| **עצירת-turn** | `turn/interrupt` | מאומת | ⚠️ לא בהכרח עוצר תהליכי-background — ראו §8 |
| שחזור/פיצול | `thread/resume`, `thread/fork`, `thread/read`, `thread/list` | מאומת | resume-by-id הוא עוגן ה-resume ל-Codex |
| צינון-משימות | `codex exec --json` (one-shot, cron/CI), מדווח reasoning-tokens | מאומת | לריצות-רקע קצרות ולוולידטורים |
| Rate-limits | token-based (מאז 04/2026); חלונות 5ש + שבועי; **בריכה משותפת** (CLI+IDE+cloud) | מאומת | הערכת-מכסה חייבת להביא בחשבון צריכה חיצונית |
| זמן-איפוס | מובנה כ-data ב-`UsageLimitReachedError` | מאומת | **קוראים את זמן-האיפוס, לא מנחשים** |
| Auto-resume אחרי איפוס | **לא מובנה** — feature-request פתוח (#21073) | מאומת | ⇐ **זו בדיוק הבעיה ש-AgentRelay פותר**. אנחנו נבנה את זה מעל. |
| Reset-banking | שמירת-איפוסים והפעלה לפי-דרישה (Go/Plus/Pro/Business) | מאומת | פיצ'ר של Codex — לא לגעת אוטומטית (8.8) |
| תקציבי-token per-thread | rollout token budgets, abort turn כשנגמר | מאומת | מזין את מגבלת-העלות שלנו |

**מסקנת-מפתח:** Codex *כבר* חושף כמעט הכל דרך App-Server מובנה — לכן ה-adapter שלו נשען על ממשק, לא על scraping של מסך. Claude Code נשלט הכי-טוב דרך SDK+Hooks. **שני העוגנים — `--resume`/`session_id` ב-Claude ו-`thread/resume` ב-Codex — הם מה שמאפשר את הבטחת "המשך אחרי איפוס".**

*מקורות §2:* [Claude Hooks reference](https://code.claude.com/docs/en/hooks) · [Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview) · [Agent SDK sessions](https://platform.claude.com/docs/en/agent-sdk/sessions) · [Codex App-Server README](https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md) · [Codex App-Server guide](https://developers.openai.com/codex/app-server) · [Auto-resume FR #21073](https://github.com/openai/codex/issues/21073) · [Codex rate-limit reset banking](https://pasqualepillitteri.it/en/news/4783/codex-save-rate-limit-resets)

## 3. ארכיטקטורת-על

```
┌──────────────────────────────────────────────┐
│  UI: Tauri window · Tray · CLI (agentrelay)   │
│  React/TS  ── IPC (Tauri commands + events) ──┤
└───────────────┬──────────────────────────────┘
                │ localhost only (loopback), token-auth
┌───────────────▼──────────────────────────────┐
│  AgentRelay Daemon  (Rust, tokio)             │
│                                               │
│  Mission Engine   Scheduler    Policy Engine  │
│  Quota Manager    Process Mgr   Timeline(ES)  │
│  Notification Hub Plugin Runtime              │
│  Context Optimizer ◄── בין Orchestrator לספק  │
│  ── Event Bus (broadcast) ── SQLite(WAL) ──   │
└───────┬───────────────┬───────────────────────┘
        │               │
┌───────▼─────┐   ┌─────▼──────────┐
│ Claude Adapter│  │ Codex Adapter  │  (+ future: Gemini, Cursor…)
│ SDK/CLI+Hooks │  │ App-Server RPC │
└───────┬───────┘  └─────┬──────────┘
        │                │
┌───────▼────────────────▼──────────────────────┐
│  Git worktrees · Filesystem · Tests · Shell    │
└────────────────────────────────────────────────┘
```

### 3.1 עקרונות מבניים
- **Daemon = מקור-האמת היחיד.** ה-UI הוא צופה חסר-מצב. סוגרים חלון → המשימה ממשיכה. זה קריטי ל-Overnight.
- **Event Bus פנימי** (tokio `broadcast`): כל מודול פולט אירועים; ה-UI נרשם דרך IPC-events; ה-Timeline צורך הכל ומתמיד ל-SQLite. אירוע אחד → כמה צרכנים (UI, timeline, notifications, watchtower).
- **גבול-אבטחה של ה-daemon:** מאזין רק ל-`127.0.0.1`, עם token מקומי שנוצר בהתקנה. שום דבר לא נחשף לרשת.
- **Adapters מבודדים מהליבה** מאחורי trait אחיד (§5). כשספק שובר API — מכבים adapter אחד, המוצר חי (דרישה 8.7).

### 3.2 בחירת-שפה: למה לא Node/Python לליבה
ניהול עץ-תהליכים חוצה-פלטפורמות (§8), signals, keep-awake, ו-daemon ארוך-חיים — קלים ובטוחים ב-Rust, וזה גם ה-runtime של Tauri, אז אין שני runtimes. את ה-SDK של Claude (שהוא TS/Python) נריץ כ-**subprocess** מנוהל — לא נכניס אותו ל-in-process. ככה הליבה נשארת דטרמיניסטית.

<a name="4"></a>
## 4. מודל הנתונים המלא (SQLite)

עקרון: **טבלת-אירועים אחת בלתי-משתנה** היא הלב; שאר הטבלאות הן projections שאפשר לבנות-מחדש מהאירועים.

```sql
-- ═══ הליבה: לוג-אירועים בלתי-משתנה (Event Sourcing) ═══
CREATE TABLE events (
  id            INTEGER PRIMARY KEY,        -- סדר מונוטוני = סדר-אמת
  mission_id    TEXT,                       -- NULL לאירועי-מערכת
  ts_utc        TEXT NOT NULL,              -- ISO-8601 UTC תמיד
  actor         TEXT NOT NULL,              -- user|claude|codex|system|validator|scheduler
  kind          TEXT NOT NULL,              -- ראו טקסונומיית-אירועים למטה
  payload       TEXT NOT NULL,              -- JSON
  seq_in_turn   INTEGER,                    -- מיקום בתוך turn
  hash          TEXT                        -- hash-שרשור לאי-שינוי (audit)
);
CREATE INDEX idx_events_mission ON events(mission_id, id);

-- ═══ Projections (נבנות מ-events) ═══
CREATE TABLE missions (
  id            TEXT PRIMARY KEY,
  title         TEXT NOT NULL,
  contract      TEXT NOT NULL,             -- Mission Contract JSON (§6)
  contract_ver  INTEGER NOT NULL DEFAULT 1,
  status        TEXT NOT NULL,             -- draft|planned|running|waiting_input|
                                           -- waiting_quota|paused|blocked|completed|failed|stopped
  autonomy      TEXT NOT NULL,             -- observe|assist|autopilot|overnight
  created_utc   TEXT, updated_utc TEXT,
  timezone      TEXT                       -- אזור-הזמן של המשתמש בעת-היצירה
);

CREATE TABLE work_units (
  id            TEXT PRIMARY KEY,
  mission_id    TEXT NOT NULL,
  seq           INTEGER,
  title         TEXT,
  contract      TEXT NOT NULL,             -- work-unit contract (allowed_paths, completion…)
  worker        TEXT,                      -- claude|codex
  status        TEXT,                      -- pending|assigned|running|review|done|failed|blocked
  worktree_path TEXT,
  session_ref   TEXT,                      -- claude session_id / codex thread_id
  result_packet TEXT,                      -- JSON (§13)
  attempts      INTEGER DEFAULT 0
);

CREATE TABLE sessions (                    -- מיפוי mission/unit ↔ session-אמיתי בספק
  id            TEXT PRIMARY KEY,
  provider      TEXT,                      -- claude|codex
  external_id   TEXT,                      -- session_id / thread_id
  work_unit_id  TEXT,
  cwd           TEXT,
  git_branch    TEXT,
  git_head      TEXT,                      -- HEAD בעת-שמירה (לאימות-resume)
  last_checkpoint_id TEXT,
  state         TEXT,                      -- active|checkpointed|resumed|dead
  created_utc   TEXT, updated_utc TEXT
);

CREATE TABLE checkpoints (
  id            TEXT PRIMARY KEY,
  mission_id    TEXT, work_unit_id TEXT,
  ts_utc        TEXT,
  git_head      TEXT, git_branch TEXT,
  git_status    TEXT,                      -- snapshot של `git status --porcelain`
  files_hash    TEXT,                      -- hash של רשימת-הקבצים+גדלים
  last_validation TEXT,                    -- JSON: אילו ולידציות עברו
  session_state TEXT,                      -- provider session refs
  summary       TEXT                       -- "מה נעשה עד כה" — לפרומפט-המשך
);

CREATE TABLE quota_snapshots (
  id            INTEGER PRIMARY KEY,
  provider      TEXT, ts_utc TEXT,
  window_kind   TEXT,                      -- 5h|weekly|context
  used          REAL, limit_val REAL,
  reset_at_utc  TEXT,                      -- מהספק — לא ניחוש
  raw           TEXT
);

CREATE TABLE scheduled_prompts (
  id            TEXT PRIMARY KEY,
  mission_id    TEXT,
  target        TEXT,                      -- claude|codex|all|commander
  trigger       TEXT NOT NULL,             -- JSON: {type:at|after|on_event|cron, ...}
  body          TEXT NOT NULL,
  condition     TEXT,                      -- JSON — נבדק לפני-שליחה
  valid_until   TEXT,                      -- תפוגה
  priority      INTEGER,                   -- ראו סולם-עדיפויות §10
  mission_ver   INTEGER,                   -- ל-invalidation אם המשימה השתנתה
  status        TEXT                       -- queued|sent|expired|cancelled|superseded
);

CREATE TABLE policies (                    -- כללים מוחלטים (שכבה-1 של Watchtower)
  id TEXT PRIMARY KEY, mission_id TEXT,
  rule_kind TEXT,                          -- forbid_path|forbid_cmd|allow_only_branch|
                                           -- no_push|no_deploy|no_net|max_files|max_cost…
  spec TEXT, enabled INTEGER DEFAULT 1
);

CREATE TABLE validations (                 -- שכבה-2
  id INTEGER PRIMARY KEY, work_unit_id TEXT, ts_utc TEXT,
  validator TEXT,                          -- tests|typecheck|build|lint|secret_scan|
                                           -- file_count|api_contract|db_migration
  passed INTEGER, output TEXT, duration_ms INTEGER
);

CREATE TABLE notifications (
  id INTEGER PRIMARY KEY, mission_id TEXT, ts_utc TEXT,
  event_kind TEXT, channel TEXT, importance TEXT, delivered INTEGER, ack INTEGER
);

CREATE TABLE processes (                   -- Process Manager — עץ חי
  pid INTEGER, mission_id TEXT, work_unit_id TEXT,
  pgid INTEGER,                            -- process-group (Unix) / job-object (Win)
  cmd TEXT, role TEXT,                     -- agent|dev_server|test_watcher|shell|child
  started_utc TEXT, alive INTEGER
);

CREATE TABLE plugins (
  id TEXT PRIMARY KEY, kind TEXT,          -- provider_adapter|trigger|action|validator|workflow_pack
  manifest TEXT, signature TEXT, granted_perms TEXT, enabled INTEGER, source TEXT
);
```

**טקסונומיית-אירועים (`events.kind`)** — הקבוצות שכל המערכת מדברת בהן:
`mission.created/started/plan_ready/completed/failed/stopped` · `unit.assigned/started/result/reviewed` · `turn.started/completed/interrupted` · `tool.pre/post/blocked` · `file.edited` · `cmd.run` · `permission.requested/granted/denied` · `checkpoint.saved` · `quota.low/exhausted/reset/resumed` · `validation.ran` · `drift.detected` · `notify.sent` · `stop.requested/completed` · `ctx.*` (Context Optimizer — ראו המסמך הנפרד).

> **הרחבת-סכמה ל-Context Optimizer** (file_receipts · artifacts · context_ledger · repo_map · savings · waste_events) מפורטת ב-[`01-context-optimizer.md §4`](01-context-optimizer.md). היא חלק מאותה מערכת-נתונים.

<a name="5"></a>
## 5. Provider Adapter — החוזה + מימוש לכל ספק

כל ספק ממומש מאחורי אותו trait. זה מה שמאפשר "Claude מפקד על Codex" ואת ריבוי-הספקים העתידי.

```rust
#[async_trait]
pub trait ProviderAdapter: Send + Sync {
    fn id(&self) -> &str;                       // "claude-code" | "codex-app" ...
    fn capabilities(&self) -> Capabilities;     // מה נתמך: resume? interrupt? hooks? steer?

    // מחזור-חיים של session
    async fn start_session(&self, spec: SessionSpec) -> Result<SessionHandle>;
    async fn resume_session(&self, ext_id: &str, spec: SessionSpec) -> Result<SessionHandle>;

    // הרצה — מחזיר stream של אירועים מנורמלים (ראו AgentEvent)
    async fn run_turn(&self, s: &SessionHandle, input: TurnInput)
        -> Result<BoxStream<AgentEvent>>;
    async fn steer(&self, s: &SessionHandle, msg: &str) -> Result<()>;   // אופציונלי
    async fn interrupt(&self, s: &SessionHandle) -> Result<()>;

    // מכסה
    async fn quota(&self) -> Result<QuotaState>;   // used/limit/reset_at לכל חלון

    // אכיפה — מתקינים hooks/policy ברמת-הספק לפני-ריצה
    async fn install_guards(&self, s: &SessionHandle, guards: &[Guard]) -> Result<()>;
}

// אירוע-מנורמל אחד שכל הספקים פולטים אליו:
pub enum AgentEvent {
    TurnStarted, TextDelta(String), ToolPre{tool:String, args:Value},
    ToolPost{tool:String, result:Value}, FileEdited(PathBuf), CmdRun{cmd:String},
    PermissionRequested{action:String}, TokenUsage(Usage),
    TurnCompleted{usage:Usage}, Error(String), RateLimited{reset_at:DateTime<Utc>},
}
```

### 5.1 מימוש Claude Adapter
- **מנוע:** ה-daemon מריץ subprocess. ברירת-מחדל: `claude -p --output-format stream-json --input-format stream-json --resume <id?>` ב-`cwd` של ה-worktree. פרסינג NDJSON → `AgentEvent`. חלופה מתקדמת: תהליך-Node קטן שמריץ את ה-Agent SDK (V2 send/stream) כשצריך שליטת-hooks עשירה יותר.
- **`start_session`:** מריץ turn ראשון, קורא `session_id` מ-`result` → שומר ב-`sessions.external_id`.
- **`resume_session`:** `--resume <session_id>` (או `--continue`). **חובה:** turn-ראשון-אחרי-resume עושה *רק* בדיקת-מצב (§9), לא עריכה.
- **`install_guards`:** כותב קובץ-hooks זמני ל-`.claude/settings.json` של ה-worktree:
  - `PreToolUse` → סקריפט שמתייעץ עם ה-daemon (`agentrelay guard check --unit <id>`), `exit 2` לחסימה, stderr = הסיבה בעברית/אנגלית. **זו שכבה-1 של Watchtower בפועל.**
  - `Stop` → אם יש completion-conditions שלא התקיימו, מחזיר `decision:block` + reason.
  - `PostToolUse` → פולט `tool.post` ל-daemon (מזין timeline + validators).
  - `Notification`/`SessionEnd` → מזינים Signal Hub.
- **`interrupt`:** שולח SIGINT/kill לעץ-התהליכים (§8), לא רק לסוכן.
- **`quota`:** קורא ממה שה-CLI מדווח + מטמון; ב-headless מזהים rate-limit מהודעת-השגיאה.

### 5.2 מימוש Codex Adapter
- **מנוע:** מריץ את ה-Codex App-Server ומדבר JSON-RPC על **stdio או Unix-socket**. אין scraping.
- מיפוי ישיר: `start_session`→`thread/start` · `resume_session`→`thread/resume` · `run_turn`→`turn/start` + צריכת-stream (`item/*`,`turn/completed`) · `steer`→`turn/steer` · `interrupt`→`turn/interrupt` **+ kill-tree** (כי interrupt לבדו לא עוצר background) · `quota` מ-`turn/completed.usage` + `UsageLimitReachedError.reset_at`.
- **fork לפני-סיכון:** לפני ניסוי מסוכן — `thread/fork`, אם נכשל חוזרים ל-thread המקורי.
- **צינון קצר:** ולידטורים ומשימות-רקע קצרות → `codex exec --json` (בלי להחזיק thread).

### 5.3 נורמליזציה — למה זה חשוב
כל ההבדלים בין הספקים נעצרים בשכבת-ה-adapter. Mission Engine, Watchtower, Timeline ו-Quota Manager מדברים **רק** ב-`AgentEvent`/`QuotaState` מנורמלים. כשמוסיפים ספק שלישי — כותבים adapter אחד, שאר המערכת לא זזה.

## 6. Mission Engine + Mission Contract

ה-Mission Contract הוא **חוזה בלתי-משתנה** (נעול לגרסה). כל שינוי דורש אישור-משתמש ומעלה `contract_ver`. זה מה שמאפשר לבדוק בכל רגע "האם הסוכן עדיין עושה את מה שהתבקש".

```yaml
# Mission Contract — הסכימה המלאה
version: 3
title: "מערכת אימות משתמשים"
goal: "בנה הרשמה, כניסה ואיפוס-סיסמה, עם בדיקות"
desired_outcome:
  - "משתמש יכול להירשם, להתחבר, לאפס סיסמה"
  - "בדיקות-יחידה ואינטגרציה עוברות"
scope:
  project_dir: "/path/to/project"
  allowed_paths: ["src/auth/**", "tests/auth/**"]
  forbidden_paths: ["deploy/**", "production/**", "**/*.css"]
completion:                      # תנאי-הצלחה = ראיות, לא הצהרה
  - kind: tests_pass
    cmd: "npm test -- auth"
  - kind: typecheck_pass
  - kind: no_new_secrets
  - kind: no_push
  - kind: no_deploy
limits:
  timeout_min: 480
  max_cost_tokens: 2_000_000
  max_files_changed: 30
  max_attempts: 3
autonomy: overnight              # observe|assist|autopilot|overnight
agents:
  commander: claude
  worker: codex
  review: claude                 # מי מבקר את מי
stop_conditions:                 # §Control Center
  - at: "07:00"
  - after_current_unit_if: build_failed_twice
  - if: dependency_added
  - if: files_changed_gt: 30
  - if: network_access_required
  - if: drift_detected
  - if: context_below_pct: 15
resume_policy:                   # §9
  on_quota_reset: verify_then_continue
  first_turn: state_check_only
notify:
  channels: [desktop_sound, phone, home_assistant]
  quiet_hours: "23:00-07:00"
  profile: overnight
guards:                          # שכבה-1, נאכף בקוד (§7)
  no_push: true
  no_deploy: true
  no_delete_outside_workspace: true
  no_auto_permission_escalation: true
  network: deny_by_default
```

**מנוע-המצבים של משימה:**
`draft → planned → running → (waiting_input | waiting_quota | paused | blocked) → running → completed|failed|stopped`

- **`draft→planned`:** ה-commander (Claude) יוצר תוכנית, מפצל ל-units, קובע תנאי-הצלחה לכל unit. במצב-אוטומטי — אישור-אוטומטי לפי כללים; אחרת מציג למשתמש (Preview חובה).
- **מ-planned והלאה** — Watchtower חי ורץ (§7).
- **מעברי-מצב הם אירועים.** אין "state" מוסתר; הכל ב-`events`.

**מצב-פשוט → Contract:** 5 השדות של "מצב פשוט" (מה/איפה/מתי-להתחיל/מתי-לעצור/איך-להודיע) עוברים תבנית ל-Contract עם ברירות-מחדל בטוחות. משתמש-מקצועי עורך YAML ישירות.

<a name="7"></a>
## 7. Policy Engine + Watchtower — 3 שכבות אכיפה

הלב של "פיקוח על סטייה". **הכלל: לא סומכים על המודל שיזכור. אוכפים בקוד.**

### שכבה 1 — כללים מוחלטים (דטרמיניסטיים, בקוד)
נאכפים דרך ה-Hooks של Claude ו-approval-policy של Codex, **וגם** בשכבת-ה-adapter עצמה כגיבוי (defense-in-depth):
- כשסוכן קורא לכלי (`ToolPre`), ה-guard בודק מול ה-policies:
  - עריכת-קובץ מחוץ ל-`allowed_paths` או בתוך `forbidden_paths` → **חסום**, החזר סיבה: "המשימה אינה כוללת שינוי הקובץ הזה. המשך בלי לגעת בו."
  - פקודת-shell שמכילה `git push`/`deploy`/`rm` מחוץ-ל-workspace → **חסום**.
  - התקנת-dependency, גישת-רשת, מעבר-branch → **חסום** אם ה-guard אוסר.
- החסימה נאכפת ב-`PreToolUse exit 2` **לפני** בדיקת-הרשאות — הסוכן לא יכול לעקוף ע"י שינוי-מצב-הרשאות. זה מדויק לתרחיש-ה-CSS באפיון (01:47).

### שכבה 2 — ולידטורים (ראיות מהמערכת)
רצים אחרי כל unit ולפני סימון-completion. כל אחד = תהליך אמיתי + פלט נשמר ב-`validations`:
`build` · `tests` · `lint` · `typecheck` · `secret_scan` (git-secrets/trufflehog) · `api_contract` · `db_migration_check` · `file_count` (כמה קבצים באמת השתנו מול המותר).
**Completion = כל הראיות עברו.** לא הצהרת-סוכן. זה הפתרון ל-8.4.

### שכבה 3 — ביקורת חוצת-סוכן
סוכן-מבקר (Claude מבקר את Codex, או להפך) מקבל: המשימה-המקורית + ה-Diff + תוצאות-הוולידציה + מגבלות-המשתמש. **שאלות ממוקדות, לא "האם זה טוב":**
1. האם כל דרישות-ה-Contract מולאו? 2. האם נוספה עבודה שלא התבקשה? 3. האם יש שינוי מסוכן? 4. האם הוכרז completion בלי ראיות?
פלט מובנה (pass/fail + נימוק לכל שאלה) → נכנס ל-`events` ולדוח.

### מנוע ה-Drift Detection (מה Watchtower משווה כל הזמן)
מריץ בכל `ToolPost`/`turn.completed`: משווה **המשימה המקורית · התוכנית · ה-unit הפעיל · קבצים-מותרים מול קבצים-שנערכו · פקודות · deps-שנוספו · פעולות-רשת · תקציב · הרשאות · משך · מס'-ניסיונות · מה-שהסוכן-טוען-שהשיג**. סטייה → `drift.detected` → פעולה לפי stop_conditions (עצור/החזר-הנחיה/בקש-אישור).

<a name="8"></a>
## 8. Process Manager — עצירה שבאמת עוצרת

הבעיה (8.2, 8.14): `turn/interrupt` או SIGINT לסוכן **לא** עוצר dev-server, test-watcher, Docker, subagent, child-shell. פתרון: **כל משימה מקבלת עץ-תהליכים מנוהל, ועצירה הורגת את כל העץ.**

### מנגנון לכל OS
- **Linux/macOS:** כל סוכן נולד ב-**process-group חדש** (`setsid`/`setpgid`). עצירה = `kill(-pgid, SIGTERM)` ואז `SIGKILL` אחרי grace. זה תופס גם נכדים.
- **Windows:** כל סוכן ב-**Job Object** (`CreateJobObject` + `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`). סגירת ה-job הורגת את כל העץ אטומית. גיבוי: `taskkill /PID <pid> /T /F`.
- **מעקב חי:** טבלת `processes` מתעדכנת כשנולד/מת תהליך; ה-daemon מנטר יתומים (תהליך עם `alive=1` שכבר לא קיים) ומנקה.

### שלוש דרגות-עצירה (מהאפיון)
| כפתור | מה קורה בפועל |
|-------|----------------|
| **Pause** | עוצר **אחרי** הפעולה הנוכחית. לא הורג. הסוכן לא מקבל turn חדש. |
| **Safe Stop** | מסיים פקודה פעילה → מריץ checkpoint → שומר-מצב → עוצר. |
| **Stop Now** | `interrupt` מיידי של ה-turn. |
| **Emergency Stop** | הורג את **כל** עץ-התהליכים של המשימה + מנתק פעולות-רשת של המשימה + מסמן "לבדיקה ידנית". **לא מוחק שינויים.** |

**החוזה עם ה-UI:** כפתור לא מסמן "עצור" עד ש-`processes` מאשרת שכל העץ מת. אם נשאר יתום — ה-UI מראה "עוצר…" עד לניקוי. ככה אין "שליטה מזויפת" (8.14).

*מקורות §8:* [Tauri sidecar kill-tree](https://github.com/orgs/tauri-apps/discussions/3273) · [keep-alive cross-platform](https://github.com/stigoleg/keep-alive)

<a name="9"></a>
## 9. Quota Manager — המשך אחרי איפוס (הפיצ'ר המרכזי)

זו ההבטחה הגדולה של המוצר, וגם נקודת-הכשל המסוכנת ביותר (8.1). הנה הפרוטוקול המדויק.

### 9.1 התקרבות-למכסה (proactive)
ה-Quota Manager דוגם `quota()` (§5) ומחשב **קצב-שריפה** מריצות-עבר של אותו משתמש/ריפו (8.6). כשמזוהה "החלון הבא לא ייכנס":
1. **לא מתחיל unit חדש.** 2. מנחה את הסוכן לסיים את הבדיקה הנוכחית. 3. Build. 4. **Checkpoint.** 5. מעביר משימה ל-`waiting_quota`.
(זה בדיוק רצף 01:47 באפיון.)

### 9.2 שמירת-Checkpoint (עוגן ה-resume)
Checkpoint = לא רק session-id. הוא שומר (טבלת `checkpoints`): `git_head` + `git_branch` + `git status --porcelain` + hash-של-רשימת-קבצים + אילו ולידציות עברו + refs-של-session-בספק + **סיכום-טקסט "מה נעשה עד כה"**. שמור ל-KV/דיסק חיצוני, לא רק בזיכרון-הספק.

### 9.3 חזרה אחרי איפוס — רשימת-בדיקה קשיחה (הליבה של 8.1)
כשזמן-האיפוס (שנקרא **מהספק**, לא נוחש) מגיע, לפני שום עבודה:
```
✓ המכסה באמת חזרה? (quota() מאשר, לא רק השעון)
✓ התיקייה עדיין קיימת?
✓ ה-branch לא השתנה? (git_branch == checkpoint)
✓ HEAD תואם? (git_head == checkpoint; אם לא — שינוי חיצוני!)
✓ אין שינוי-קבצים חיצוני? (files_hash תואם)
✓ ה-session/thread המתאים זמין?
✓ ה-checkpoint תקין?
✓ ההרשאות לא הורחבו?
✓ אין תהליך-ישן שעוד רץ? (processes נקי)
```
כל כשל → **לא ממשיכים אוטומטית**; מעלים ל-`waiting_input` + התראה.

### 9.4 ה-Turn הראשון אחרי resume — קריטי
מהמחקר: אחרי rate-limit, session עלול לשכוח את ההוראה האחרונה / לחזור להקשר-קודם / לבצע-מחדש עבודה. לכן:
- **Turn-ראשון = בדיקת-מצב בלבד.** הפרומפט מזריק את סיכום-ה-checkpoint ומבקש מהסוכן לאשר שהבין את המצב (מה נעשה, מה ה-HEAD, מה ה-unit הבא). **אסור לערוך עד שהסוכן אישר את ה-checkpoint.**
- רק אחרי אישור — משחררים את ה-unit הבא.
- אם הסוכן "מתחיל מחדש" משהו שכבר עבר ולידציה — Watchtower חוסם (drift).

### 9.5 החלטת-Resume (מה עושים בפועל)
ה-Quota Manager בוחר: (א) לחדש אותו session · (ב) session נקי חדש עם checkpoint מוזרק · (ג) להעביר את ה-unit ל-Codex · (ד) לעצור ולשאול אותך. הבחירה נגזרת מבריאות-ה-session ומ-`resume_policy` ב-Contract.

**כלל-ברזל:** לעולם לא מרחיבים הרשאות אוטומטית אחרי resume, ולעולם לא משתמשים אוטומטית ב-reset-banking של Codex (8.8) — זו החלטת-משתמש.

*מקורות §9:* [Auto-resume FR #21073](https://github.com/openai/codex/issues/21073) · [Agent SDK sessions](https://platform.claude.com/docs/en/agent-sdk/sessions)

## 10. Scheduler — תור-פרומפטים חסין-התיישנות

הבעיה (8.3): פרומפט שתוזמן ב-23:00 עלול להיות שגוי ב-03:00. הפתרון: **כל פרומפט נבדק מול המצב לפני-שליחה.**

### סוגי-טריגר
`at:<זמן>` · `after:<משך>` · `after_unit:<id>` · `on_event:<kind>` (build-ok, test-fail, idle, quota-reset, context>threshold, file-added, permission-needed, agent-claims-done, no-activity) · `cron:<expr>`.

### כל פרומפט-מתוזמן נושא:
`target` · `trigger` · `condition` (נבדק לפני-שליחה) · `valid_until` (תפוגה) · `priority` · `mission_ver` · `preview` · `reason` · אפשרות-ביטול.

### שער-השליחה (זה מה שמונע פרומפט-מיושן):
לפני שליחה ה-Scheduler בודק: (1) `mission_ver` עדיין תקף? אם המשימה השתנתה → **superseded**, לא נשלח. (2) `valid_until` לא עבר? (3) ה-`condition` עדיין מתקיים מול המצב-הנוכחי? (4) יש audit-trail. פרומפט שנפסל נרשם כ-`expired`/`superseded` ב-`events` — **לעולם לא נשלח לסוכן בטעות.**

### סולם-עדיפויות (קשיח)
```
1. עצירת-חירום
2. כלל-אבטחה
3. הוראה ידנית של המשתמש
4. הוראה מתוזמנת
5. המשך אוטומטי
6. פעולת-רקע רגילה
```
התנגשות → העדיפות-הגבוהה מנצחת; הנמוכה נדחית/מבוטלת עם סיבה גלויה.

## 11. Timeline — Event Sourcing

ה-Timeline הוא פשוט **תצוגה של `events`**. כל דבר עם חותמת-זמן: הודעת-משתמש, תשובת-Claude, תשובת-Codex, פקודה, עריכת-קובץ, בקשת-הרשאה, checkpoint, עצירה, חידוש, שינוי-מכסה, תוצאת-בדיקה, התראה.

**זמן:** נשמר **תמיד UTC** ב-`events.ts_utc`; מוצג לפי אזור-הזמן של המשתמש. המשתמש בוחר: שעה-מקומית / תאריך+שעה מלא / יחסי ("לפני 17 דקות") / הצגת-אזור-זמן / הפרדת היום·אתמול·קודם / משך כל turn. שמירה ב-UTC פותרת החלפת-מחשב, שעון-קיץ, ודוחות-אמינים (§6 בארכיטקטורה).

**ביצועים:** virtualized list ב-UI (react-window); ה-daemon שולח דלתא-אירועים דרך IPC-events, לא re-fetch.

## 12. Notification Hub + בית חכם

**אירועים:** התחלה · unit-הושלם · ממתין · נדרשת-הרשאה · סטייה · build-נכשל · מכסה-נגמרה · מכסה-חזרה · session-חודש · הושלם · נעצר · תוצאה-חלקית.

**ערוצים:** Desktop notification · צליל-מקומי · טלפון (push) · מייל · Slack · Discord · Telegram · Webhook · **Home Assistant** · MQTT · פקודת-מערכת מותאמת.

**מניעת התראות-יתר (8.11):** profiles + שעות-שקטות + **קיבוץ-אירועים** + רמות-חשיבות + **התראה-אחת-לכל-חסם** + escalation רק אם לא-התקבלה-תגובה. אחרת המשתמש מכבה הכל.

**Home Assistant — קונקרטי:** חיבור דרך **long-lived token + REST/webhook** ל-`http://<ha>:8123/api/webhook/<id>`. שולחים event מובנה:
```json
{"event":"mission_completed","mission":"authentication","status":"success"}
```
מיפוי-דוגמה: ירוק=הושלם · צהוב=ממתין-למכסה · אדום=נדרשת-התערבות · TTS "משימת-הלילה הושלמה".
**גבול-אבטחה:** integration מוגדר, לא גישה-חופשית לבית. פעולות-בטיחות (מנעולים/דלתות/תנורים/אזעקות) **חסומות כברירת-מחדל**. Webhooks מקומיים בלבד.

<a name="13"></a>
## 13. Relay Orchestrator — מפקד/מבצע

```
משתמש → AgentRelay → Claude(מפקד) → Codex(מבצע) → Validators → Claude(מבקר) → אישור-סופי
```
**מפקד (Claude):** מבין-כוונה · מתכנן · מפצל-עבודה · קובע-סדר · בוחר-worker · בודק-תלויות · סוקר-תוצאות · מחליט תיקון/התקדמות · כותב-דוח.
**מבצע (Codex):** מקבל unit צר · עובד ב-worktree מבודד · עורך · מריץ-בדיקות · מחזיר Result-Packet · מתקן-לפי-משוב.

**Result-Packet אחיד** (מוחזר מכל worker, נכתב ל-`work_units.result_packet`):
```json
{"task":"password-reset-api","status":"completed","changedFiles":[],
 "commands":[],"tests":[],"decisions":[],"remainingRisks":[],"blockedBy":null}
```

**מניעת-התנגשויות (8.5):** כל worker ב-**git worktree משלו** (branch נפרד). בעלות-על-קבצים + task-boundaries + lock + merge-queue + בדיקת-conflicts + "קבלת-עבודה" (review עובר) **לפני** מיזוג. שני סוכנים לעולם לא עורכים אותו קובץ במקביל.

**תבניות (החלפת-תפקידים):** Claude-plans/Codex-implements · Codex-plans/Claude-reviews · Claude-implements/Codex-audits · שניים-מציעים-והמפקד-בוחר · worker-יחיד+validator-דטרמיניסטי · כמה-workers-במקביל. המוצר לא מקבע ש-Claude תמיד מפקד.

**מודעות-מכסה בתכנון:** המפקד יודע כמה מכסה נשארה (§9) וקובע גודל-unit בהתאם — לא מתחיל unit-ענק כשהמכסה נמוכה.

<a name="14"></a>
## 14. Plugin Runtime + מודל-אבטחה

**לא בונים marketplace מתחרה.** מוסיפים שכבת-Extensions לדברים שהספקים לא מנהלים יחד: **Provider-Adapter · Trigger · Action · Validator · Workflow-Pack**.

**Workflow-Pack** = חבילה מתקינה: mission-template + commander-config + worker-config + validators + safety-policy + notification-profile. דוגמאות: "בניית-Feature בלילה", "מחקר+דוח", "בדיקת-אבטחה", "טיפול-ב-Issues", "סקירת-PR".

**מודל-אבטחה (8.9) — כי plugins/memory/README הם וקטור-הזרקה:**
- **חתימת-plugins** + הרשאות-מפורשות (מה ה-plugin רשאי: קבצים? רשת? הרצת-פקודות?).
- **Sandbox** להרצת-plugin (תהליך מבודד, הרשאות-מוגבלות).
- **הפרדת-מידע-מהוראות:** תוכן שמגיע מ-plugin/memory/README מסומן כ-**מידע**, לעולם לא מתפרש כפקודה. Plugin **לא** יכול לשנות Policy בלי אישור-מפורש.
- **Review למסמכי-Memory** + הצגת-מקור-כל-הוראה. זה תואם לגבול-האמון של המערכת כולה (§1).

<a name="15"></a>
## 15. בין-לאומיות ו-RTL

לא תרגום-אוטומטי-שטחי (8.13). מנגנון קונקרטי:
- **הפרדה מלאה טקסט↔קוד.** אין מחרוזות בקוד; הכל בקובצי-משאבים (`i18next` / ICU JSON).
- **ICU MessageFormat** לרבים/מין/מספרים.
- **RTL אמיתי:** `dir="rtl"`, logical CSS properties (`margin-inline-start`), בדיקות-פריסה ל-RTL, בדיקת-טקסט-ארוך, בדיקת-תערובת עברית+קוד+מספרים.
- **פורמט-תאריך/שעה מקומי** (Intl API) — נגזר מאזור-הזמן של §11.
- **שתי הגדרות-שפה נפרדות:** שפת-ה-UI (למשל עברית) ≠ שפת-העבודה-של-הסוכן (פרומפט טכני באנגלית). זו דרישה מפורשת.
- **Glossary קבוע** + תיקון-תרגום מקובצי-משאבים + דוברי-שפת-אם לביקורת.
- Unicode מלא בשמות-קבצים.

## 17. תוכנית-בנייה בשלבים אטומיים

עיקרון: **הוכחה-מוקדמת של הליבה המסוכנת ביותר.** לא בונים UI יפה לפני שהוכחנו שמשימה שנעצרה בלילה ממשיכה בבטחה. כל שלב נגמר ב"מה-מוכיח-שזה-עובד".

- **מוכיח:** אירוע נכתב, נקרא, מוצג ב-CLI עם חותמת-UTC.

- [ ] **Context Optimizer — גרעין:** File Receipts + Tool Output Compressor + artifact-store + Context-Health בסיסי. (הפיצ'ר-הראשון של המודול; ניתן-למדידה, עובד עם Claude ו-Codex, לא-תלוי-מודל.)

## 18. שאלות פתוחות — צריך החלטה שלך

אלה ההחלטות שלא יכולתי/לא-צריך להכריע לבד. סימנתי המלצה לכל אחת:

1. **טכנולוגיית-UI:** אישרתי Tauri 2 + React. אם אתה מעדיף Electron (מוכר יותר) או Tauri+Svelte (קל יותר) — תגיד. **המלצתי: Tauri+React.**
2. **מנוע-Claude:** SDK (node subprocess) מול CLI-headless בלבד. SDK נותן hooks עשירים אך מוסיף תלות-node. **המלצתי: להתחיל ב-CLI-headless (Phase-1), לעבור ל-SDK ב-Phase-2 כשצריך hooks עשירים.** אישור?
3. **היקף-Phase-1:** האם ה-MVP צריך גם Codex, או Claude-בלבד מספיק להוכחת-הליבה? **המלצתי: Claude בלבד** — זה כל מה שצריך כדי להוכיח את resume-אחרי-איפוס, שהוא ה-raison d'être.
4. **תוכניות-הספקים שלך:** אילו תוכניות יש לך ב-Claude וב-Codex? (משנה את חלונות-המכסה ואת חיזוי-השריפה §9.1). צריך את זה לפני שאני בונה את ה-Quota Manager באמת.
5. **Home Assistant:** יש לך מופע רץ? כתובת+טוקן? (משפיע אם בונים אינטגרציה-מלאה או stub ב-Phase-2).
6. **רישוי/מסחור:** קוד-פתוח? מוצר-בתשלום? צוותים? (משפיע על telemetry, remote-runners, signing).
7. **סדר-עדיפות אישי:** מה הכי דחוף לך לראות עובד — resume-אחרי-לילה, או מפקד/מבצע Claude+Codex? אני בנוי לפי resume-קודם; תוכל להפוך.
8. **מפת-הריפו של Context Optimizer:** לבנות מנוע-מפה חדש (tree-sitter), או **לאמץ את Graphify** שכבר בשימוש שלך (god-nodes/imports/communities)? **המלצתי: לאמץ Graphify כבסיס-המפה** — פחות-קוד, כבר-מוכח אצלך, אפס-עלות-LLM. צריך אישור עקרוני.
